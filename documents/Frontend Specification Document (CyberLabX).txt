1.  Design  Philosophy  
CyberLabX  should  not  look  like  a  typical  college  ERP  portal.  
It  should  feel  like  a  modern  cybersecurity  platform  while  remaining  approachable  for  students  
who
 
are
 
new
 
to
 
security.
 
Design  principles:  
●  Professional  ●  Minimal  ●  Dark-first  ●  High  contrast  ●  Fast  ●  No  unnecessary  animations  ●  Accessibility  compliant  ●  Terminal-inspired,  not  "hacker  movie"  inspired  
Avoid  the  common  mistake  of  using  neon  green  text  on  black  everywhere.  Use  those  accents  
sparingly.

23.  Frontend  Performance  Guidelines  
●  Lazy-load  experiment  pages.  ●  Code-split  the  terminal  and  analytics  modules.  ●  Optimize  icon  imports  (tree-shaking).  ●  Virtualize  long  tables  (student  lists,  logs).  ●  Debounce  search  inputs.  ●  Cache  experiment  metadata  with  TanStack  Query.  ●  Show  skeleton  loaders  instead  of  blocking  spinners  where  possible.  
 
Architectural  Recommendation  
There  is  one  change  I  would  make  before  writing  any  UI.  
Do  not  design  the  interface  around  "pages."  Design  it  around  application  states .  
For  example,  the  Lab  page  isn't  a  single  screen—it  has  distinct  states:  
●  Lab  not  started.  ●  Lab  starting.  ●  Lab  running.  ●  Lab  disconnected.  ●  Lab  reconnecting.  ●  Lab  completed.  ●  Lab  expired.  ●  Lab  failed.  
Likewise,  the  Experiment  page  can  be  in  draft,  available,  locked,  assigned,  or  completed  states.  
Designing  these  states  first  will  produce  a  more  resilient  interface  than  simply  creating  static  
page
 
mockups.
 
It
 
also
 
gives
 
frontend
 
developers
 
a
 
clear
 
contract
 
for
 
how
 
the
 
UI
 
should
 
behave
 
as
 
the
 
backend
 
responds
 
to
 
different
 
conditions.
 
This
 
state-driven
 
approach
 
is
 
common
 
in
 
mature
 
SaaS
 
products
 
and
 
will
 
make
 
CyberLabX
 
significantly
 
easier
 
to
 
maintain
 
as
 
new
 
experiments
 
and
 
features
 
are
